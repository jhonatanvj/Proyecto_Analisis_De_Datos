# Ingestion Contract Draft (Workshop #1)

Scope: **United States volcanoes** (165 GVP Holocene volcanoes with `Country = 'United States'`, plus HANS volcanoes outside the Holocene list). General rules for all sources:

* Every response is first written **unmodified** to the raw landing zone (`data/raw/<source>_YYYYMMDD_HHMMSS.<ext>` + `.meta.json` with URL, headers and SHA-256). Processing reads from the landing zone, so any run can be re-processed without calling the API again.
* Writes are **upserts** on the duplicate key: `INSERT ... ON CONFLICT (event_id) DO UPDATE ... WHERE content_hash <> EXCLUDED.content_hash`. Re-running any mode produces no duplicates.
* One `ingestion_run` row per source and execution (`running` → `success`/`failed`), with `rows_in`, `rows_new`, `rows_updated`, `rows_rejected`.
* **The watermark advances only in the same transaction that commits the data** for that source. If a run fails halfway, the transaction is rolled back, the watermark keeps its old value, and the next run repeats the same interval. Upserts make that repetition harmless.
* HTTP: timeout (10 s connect / 120 s read), up to 4 retries with exponential backoff (2, 4, 8, 16 s) on 429/5xx, honoring `Retry-After`; a polite `User-Agent` with a contact; conditional requests (`If-None-Match` / `If-Modified-Since`) where the server sends ETag/Last-Modified.

**Optional source — Weekly Volcanic Activity Report (RSS).** Kept as context for the dashboard, not as one of the two required incremental sources: only 2 of 27 items in the current report are US volcanoes, and the feed was not updated between 15 Oct and 9 Nov 2026 (`Last-Modified: Thu, 15 Oct 2026 19:11:09 GMT`). Strategy: poll every 6 h with `If-None-Match`/`If-Modified-Since`; keep items whose `guid` vnum is a US volcano; duplicate key `(vnum, week_start)`; watermark max(`week_end`).

**Failure in the middle of a run.** Each source is committed in its own transaction together with its `ingestion_state` row. If FDSN fails after 80 of 165 volcanoes, the transaction for that partition is rolled back and the watermark keeps its old value; the next run repeats the missing partitions, and the upserts make the repeated rows harmless. Raw files already written stay in the landing zone, so a re-run can re-process them without calling the API again.

Optional extension (only if time allows): GDACS events API (`eventlist=VO`, watermark `datemodified`).
